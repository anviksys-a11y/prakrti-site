# Prakrti GSA 紹介サイト（本番用）

紹介サイトの本番用のファイル一式です。英語のページは `/`、日本語のページは `/ja/` に置きます。アプリとは別の静的なサイトなので、アプリを直したり止めたりしても影響しません。

## 中身

| ファイル | 役目 |
|---|---|
| `src/site.html` | 本文。英語と日本語を `class="en"` と `class="ja"` で並べた一つの原稿 |
| `src/site.css` | 見た目 |
| `src/site.js` | 動く部分（三国の地図、世界地図、御者と射手の体験版、聖句盤の小さなギーター（`renderLens`）、語学教室のクイズの体験版（`renderLangQuiz`）、アプリの描き方の三国の地図（`renderAppMap`）、Yātrā の一枚の体験（`yatraDemo`）、コピーのボタン） |
| `src/fonts/` | サイトの書体 6 種（すべて SIL Open Font License）。`fonts.css` が書体の一覧 |
| `site.config.json` | サイトの URL、連絡先、招待フォームの URL |
| `build.py` | 原稿から `dist/` を作る |
| `dist/` | 公開するファイル（24 ページ、404、サイトマップ、robots.txt、アイコン、書体） |
| `firebase.json` | Firebase Hosting の設定（きれいな URL、キャッシュ、セキュリティの見出し） |

## 文を直すとき

1. `src/site.html` を直します。英語と日本語の両方を直してください。
2. `python3 build.py` を実行します（初回だけ `pip install beautifulsoup4 budoux` が要ります）。
3. 次のどれかに当たると、build は止まって場所を知らせます。
   - 画面の言葉の決まりで使わない語（救い・悟り・修行・カウンセリング・癒やし・浄化、salvation・enlighten・guru・therapy・heal・chosen）
   - 英語のページに日本語の字が出ている（特商法の日本語の原文の表だけは例外で、`lang="ja"` を付けてあります）
   - 切れたリンク、欠けた書体のファイル、ページの中に無い行き先（`#prism` や、ほかのページの `#writing` など）
   - ほかのサイトから読み込むもの（書体・スクリプト・画像など）

## リンクの書き方

- ほかのページへ：`href="#engine"`（`site.js` の `SLUG` と `build.py` の `PAGES` にある名前）
- ほかのページの中の場所へ：`href="#principles#writing"`（原則のページの `id="writing"` へ）
- 同じページの中の場所へ：`href="#prism"`
- アプリへ：`href="#app"`、アプリの中のページへ：`href="#app:/observe"`

## 三国の地図

トップの大きな地図、判定のしくみのページの「叙事詩の場面」、共有の画像は、どれも `src/site.js` の同じ部品（サイトの絵柄）で描いています。Sutra の使い方を見せる所（トップの「流れの例」の三、判定のしくみの § 5）だけは、アプリと同じ描き方の地図を使います（下の「アプリの描き方の地図」）。

- **形の決まりはアプリと同じです。** 国の広さは五つの段、欲は圧の四つの段、都どうしの近さは結び（道）で決まり、凍結では道がすべて切れて利が尽き、どれかの道が「手を結んだ」になると利と法の同盟がほどけます（アプリの `realmHex.ts`・`realmShapes.ts`・`mapReading.ts` の写し）。
- **絵柄はサイトのものです。** アプリは空いた盤の上に国ごとのマスの数を描きますが、サイトはすべてのマスをいちばん近い都の国に塗り分けます（国が広いほど、遠くまで届きます）。判定のしくみのページに、その旨を一行書いてあります。
- **場面は `SCENES`（`site.js`）にあります。** アプリの `MAP_SCENES` と同じ六つの場面・七枚です。アプリの場面の文や形が変わったら、ここも直します。日本語は「聖クリシュナ」、英語は「Sri Krishna」と書きます。
- **トップの地図は、場面を 6.5 秒ごとに順に見せます。**「一時停止」で止まり、場面のボタンを押すとその場面で止まります。マウスやキーボードの操作中、画面の外にあるとき、動きを減らす設定の端末では動きません。
- **ほかの場所に置くとき：** `<div data-realm-map="vow"></div>` で場面の地図を一枚、`<div data-realm-shape='{"kama":"strained","dk":"nearing"}'></div>` で形を書いた地図を一枚描けます（`data-legend` を付けると凡例も出ます）。

### アプリの描き方の地図（Sutra の使い方を見せる所）

2026-10-23 の社長の指示で、Sutra の使い方を説明する所は、サイトの美しい絵柄ではなく、本番の実践的な地図にしました。トップの大きな地図と、判定のしくみの § 6「叙事詩の場面」は、サイトの絵柄のままです。

- **置き方：** `<div class="app-screen" data-app-map="felt"></div>`。`src/site.js` の `APP_MAPS` に地図があり、`renderAppMap` が描きます。
- **中身の出どころ：** アプリの「三国の地図の読み方」（`/mahabharata/three-realms`）の「点線の国境——あなたが感じた地図」の見本を、2026-10-23 に写しました。盤は辺 11.5 の平らな六角が 19×13（viewBox `-170 -150 340 270`）。国のマス（12・7・12）、都、道（法と欲は「まだ近いが離れつつある」の破線、利と法は「いつもの同盟」）、本音メモから描いた点線の国境（7・12・7）、地名の位置、地図の文は、アプリの値そのままです。国のマスの並び（都、その六つの隣、次の輪のうち東を除く五つ）は `aRing` が作ります。
- **色：** アプリの暗い画面の色（盤 `#0b0b0e`、法 `#C5A880`、利 `#8FB8A8`、欲 `#D4917E`）を、サイトの明暗どちらの表示でも、そのまま使います。アプリの画面を見せる所だからです。
- **アプリの地図の描き方が変わったら**（地図の物差しの版 map-1 が改まったときなど）、同じ見本を写し直して `APP_MAPS` を直します。

## build が自動でしていること

### 書体はサイトの中に置く

書体は Google Fonts から読み込まず、このサイトの中（`dist/assets/fonts/`）に置いています。こうすると、ページを開いた人の情報（IP アドレスなど）がほかの会社に渡りません。読み込みの先が一つ減るので、表示も安定します。

日本語の書体はとても大きいので、Google Fonts と同じように、字の範囲ごとに小さなファイルに分けてあります。build は、サイトで使っている字を含むファイルだけを `dist/` に写します（いまは 540 のうち 293、6.6 MB）。見る人がダウンロードするのは、そのページに出る字のファイルだけです。文に新しい漢字を足しても、build し直せば必要なファイルが自動で加わります。

書体の出どころは Fontsource（npm の `@fontsource/*` 5.3.0）です。書体を替えるときは、`src/fonts/fonts.css` と `src/site.css` の `--font-*` を直します。

### 日本語の見出しは、文節の切れ目で改行する

日本語の見出し・リード文・ボタンは、語の途中で改行しないようにしています（例：「ひと／つの」と割れない）。Chrome にはこの機能がありますが、iPhone の Safari と Firefox にはないので、build が文節の切れ目に `<wbr>`（ここで改行してよいという印）を入れています。切れ目は BudouX（Google の日本語の文節分け）で決めます。

### スマホでは、横に広い表を縦に並べ直す

幅 640px 以下の画面では、列の多い表（Premium の段ごとの表など）を、行ごとのカードに並べ直します。各セルの上には列の名前が出ます。列の名前は build が見出しから写します。スマホで短い名前にしたいときは、見出しに `data-short-en="…"`（日本語は `data-short-ja`）を付けます。

### 共有の画像

SNS や LINE でリンクを共有したときに出る画像は `src/og/og-en.png` と `og-ja.png` です（1200×630）。左に名前と見出し、右に三国の地図（場面「ギーターの終わり」）が入ります。トップの見出しや地図を変えたら、`python3 build.py` のあとに `python3 tools/make_og.py` を実行し、もう一度 `python3 build.py` を実行します（地図の場面は、`make_og.py` の `SCENE` で選べます）。画像の URL は `site.config.json` の `base_url` から作るので、独自のドメインがつながってから表示されます。

### 公開の前に、全部のページを確かめる

```
python3 build.py
python3 tools/check_site.py
```

`tools/check_site.py` は、`dist/` を Firebase と同じ形（きれいな URL、セキュリティの見出し）で手元に出し、24 ページを PC の幅（1280）とスマホの幅（390）で本物のブラウザで開きます。見つけるもの：スクリプトのエラー、読み込めないファイル、セキュリティの見出しで止められた読み込み、画面より横に広いページ、サイトの中の切れたリンクと、行き先に無い `#id`（世界地図など、`site.js` が描くリンクも含みます）。問題があれば一覧を出して止まります。

公開のあとは、本番を同じように確かめます（`<sha>` は commit の番号。ブラウザの古い控えを避けるためです）。

```

```

初回だけ `pip install playwright && playwright install chromium` が要ります。手元で見るだけなら `python3 tools/serve_like_firebase.py` で http://127.0.0.1:8765/ に出ます。

## 直して公開する流れ（GitHub）

このフォルダは GitHub の `anviksys-a11y/prakrti-site` に置いてあり、公開は自動です。

- **main に変更が入ると**、GitHub が `build.py`（検査つき）を実行し、https://prakrti-site.web.app に公開します（`.github/workflows/deploy-live.yml`）。検査で問題が見つかったときは公開しません。
- **プルリクエストを出すと**、確認用の仮のアドレスに公開し、そのアドレスをプルリクエストに書き込みます（`deploy-preview.yml`、7 日で消えます）。見て問題なければ main に取り込むと、本番に反映されます。
- GitHub と Firebase をつなぐ鍵は、GitHub の Secrets の `FIREBASE_SERVICE_ACCOUNT_PRAKRTI_SITE` です（`firebase init hosting:github` で登録）。
- `dist/` は GitHub には置きません。毎回 GitHub の上で組み立てます。
- **見た目と動きのファイルには「版の印」が付きます。** `firebase.json` は `assets/site.css` と `assets/site.js` をブラウザに一時間とっておかせます。そのままだと、公開のすぐあとに前にも来た人が「新しいページ＋古い site.js」を受け取り、新しく足した部分が描かれないことがあります（2026-10-23 に実際に起きました）。そこで `build.py` は、二つのファイルの中身から作った短い印（`?v=580a42ea59` のような形）をページのリンクの後ろに付けます。中身が変わると印も変わるので、ブラウザは必ず新しいファイルを取りに行きます。手で何かする必要はありません。

## 手で公開する（Firebase Hosting の場合）

1. `npm install -g firebase-tools`
2. `firebase login`
3. このフォルダで `firebase use --add` を実行し、使う Firebase のプロジェクトを選びます（アプリの GCP プロジェクトに Firebase を足すか、紹介サイト用に新しく作ります）。
4. `python3 build.py` のあと、`firebase deploy --only hosting`
5. Firebase のコンソールの Hosting で「カスタムドメインを追加」から `prakrti.anviksys.com` を登録し、表示される DNS のレコードを、anviksys.com を管理している会社の画面に追加します。HTTPS の証明書は自動で発行されます。

`firebase.json` のセキュリティの見出し（Content-Security-Policy）は、このサイトの中のものしか読み込ませない設定です。あとで解析のツールなど外のものを足すときは、ここに送り先を足さないとブラウザが止めます。

Cloudflare Pages などほかの静的ホスティングでも、`dist/` をそのまま置けば動きます（セキュリティの見出しは、そのホスティングの設定で同じものを付けます）。

## 検索に出さない（2026-10-24 から）

社長の指示で、アプリの完成度が上がるまで、このサイトを検索エンジンに載せません（アイデアを見られないようにするため）。いまは次の二つで隠しています。

- `site.config.json` の `"search_indexing": false` → build が全ページに `<meta name="robots" content="noindex, nofollow">` を入れ、`robots.txt` からサイトマップの行を外します。
- `firebase.json` の `**` の見出しに `X-Robots-Tag: noindex, nofollow` → 画像・CSS・書体を含む全部のファイルに、同じ印を付けます。

クロールは止めていません（`robots.txt` は `Allow: /`）。止めると、検索エンジンが noindex の印を読めず、よそからのリンクだけでアドレスが載ることがあるためです。アドレスを知っている人は、これまでどおり開けます。

**検索に載せるとき**：`"search_indexing": true` にし、`firebase.json` の `X-Robots-Tag` の行を消して、build・公開します。その前に、独自のドメイン `prakrti.anviksys.com` をつなぎます（canonical・サイトマップ・robots.txt がこのドメインを指しているため。「手で公開する」の 5）。そのあとで Google Search Console に登録し、サイトマップを出します。

## 招待の受け付け

いまは受け付けを止めています（`site.config.json` の `"invite_open": false`）。招待の欄には「テストローンチと同時に始めます」とだけ出て、「招待を申し込む」という言葉もボタンも出ません。

テストローンチのときは、次のどちらかにして build し直し、公開し直します。

- `"invite_open": true` だけにする → 招待の欄にメールの連絡先（コピーのボタンつき）が出ます。トップの二つ目のボタン（いまは「Premium について」）も「招待を申し込む」に変わります。いちばん目立つボタンは「Prism を無料で使う」のままなので、招待を前に出したいときは、`src/site.html` のトップのボタンの順を入れ替えます。
- `"invite_open": true` にして、`invite_form_url` に Google フォームの URL を入れる → 「招待を申し込む」のボタンが出ます。

フォームの項目の推奨：お名前、メールアドレス、関心のあること（Sutra による自己探究／聖典とサンスクリット／Mahābhārata RPD／ヨガの学校）、学校の場合は受講生の人数と講座の始まる時期、ひとこと（任意）。
